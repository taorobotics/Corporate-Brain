# Windows 安装向导

本次实现依据已选[安装向导效果图](design/approved/windows-installer-wizard.png)。设计图的百分比、版本与磁盘容量是示例；实际程序读取安装引擎和当前磁盘数据，不用计时器伪造安装进度。

## 安装规则

- 首次安装优先使用固定、可写的 D 盘，推荐 `D:\Applications\Corporate Brain`。D 盘不可用或不能写入时，沿用当前用户的程序目录；可浏览更改位置。
- 发现已注册安装时保留原路径和安装范围，显示旧版与本次版本。不会把 C 盘旧安装自动迁到 D 盘。
- 新安装使用空的产品专用目录，拒绝覆盖无关文件；安装前同时检查目标盘、临时目录的空间和写入权限。静默安装也执行检查。
- 程序目录与个人记录、公司连接及更新缓存分开。改变安装目录不迁移个人数据，不修改公司数据库。
- 支持选择是否创建桌面快捷方式，不添加开机自启或捆绑软件。MIT 与隐私说明可在安装器离线打开。

## 页面与执行

欢迎、安装位置、安装中、完成四页使用原生 NSIS 控件、系统中文字体、暖白配色及陶土色主按钮。Win32 辅助模块负责页面绘制、原生进度读取、加载动画和取消协调，不访问员工内容，不申请额外系统权限，也不要求员工另装运行库。

安装页保留真正的 NSIS 进度控件；百分比取自该控件。加载动画通过原生窗口计时器切换 Phosphor CircleNotch 图标帧，独立于安装脚本变量。安装项目由实际检查、解压准备、程序写入、快捷方式/卸载注册及完成检查阶段更新；显示引擎提供的当前操作。没有预估倒计时或虚构下载速度。

先把完整应用准备到 NSIS 私有临时目录，再卸载旧版并提交新文件。解压准备期间可确认取消，等当前解压结束后退出，保留旧安装。短暂的实际覆盖写入阶段禁用取消，防止用户主动中断导致半升级。文件写入失败提供原生重试/取消提示。断电、强杀或磁盘故障下的完整旧版回滚尚未承诺，必要时重新运行安装器；这些操作不清除个人记录。

进度页直接装饰安装引擎拥有的原生页面，保留其页面切换和进度消息；欢迎、目录、完成页使用 nsDialogs。确认取消与进入写入阶段由 Win32 原子状态协调，确认弹窗尚未结束时不会卸载旧版；加载动画和准备阶段的取消确认不并发执行 NSIS 脚本回调。接受取消后禁用重复请求，等待准备步骤安全结束。

应用运行中时要求用户保存并自行关闭；不调用强制终止进程。完成页的“立即打开”启动实际客户端，“完成”仅关闭安装器。新装后的公司连接和员工登录仍在客户端内完成。

卸载入口注册在 Windows“已安装的应用”。卸载确认、进度、完成页保留本机对话、个人草稿与设置。安装器和卸载器拒绝 `--delete-app-data`，避免该参数传给旧版卸载程序。卸载不清理公司服务或 NAS。

## 构建与验证

Windows 构建需要 Node、Visual C++ x86 工具链和 Windows SDK；GitHub Windows runner 自带相关工具。员工安装不需要这些开发工具。自有辅助 DLL 使用系统 Win32 库，不携带独立 VC++ 运行库；构建检查其 x86 格式。安装/卸载生命周期继续使用 electron-builder 的上游 NSIS 原语，生成时核对替换点，防止依赖升级后悄然失配。

`pwsh -NoProfile -File scripts/verify-installer.ps1` 只检查本机安装前 UI 并取消。`-FullLifecycle -PreviousInstaller ...` 仅允许全新的 GitHub Windows runner，发现已有安装或个人目录即拒绝，防止测试覆盖实际员工数据。测试使用固定摘要的 v0.2.2、工作区内的专用安装目录和合成记录，覆盖取消、升级、打开、卸载和记录保留。它不等于员工物理设备、企业安全策略或可信签名验收。

Windows installer lifecycle 工作流先验证 main 上的开发版本；正式 Desktop release 在版本标签上重新构建并运行相同生命周期检查。只有完整检查通过才发布。Windows 仍未签名；Mac 继续使用 DMG，只有 ad-hoc 签名，无 Developer ID 或公证。
