## 1 产品目标与首版成功标准

为员工提供统一的 AI 工作入口，重点完成图片创作、视频制作、本地文件处理，以及从成功对话中创建、测试、发布和复用 Skills。公司通过管理后台维护账号、权限、知识资料、模型连接、技能版本和使用额度。

首版的核心验收场景是：员工 A 登录，引用自己有权使用的本地素材和公司资料，完成图片或视频任务并保存成果；将成功流程沉淀为可参数化的 Skill，试运行后提交；审核员批准并发布；员工 B 在另一台电脑和一个新会话里安装该技能，换一套素材完成同类任务。

员工 B 不依赖 A 的完整聊天记录、个人密钥、个人电脑绝对路径或超出 B 权限的公司资料。发布 Skill 不授予额外的数据权限。

完整对话记录属于员工本机数据。员工主动选择记录，提炼为个人 Skill 草稿，再将确认过的 Skill 包提交公司平台；平台审核发布后，其他员工下载并在自己的环境中使用。公司平台不集中归档员工的完整聊天历史。

## 3 产品组成和职责

| 组成 | 主要职责 | 运行位置 |
| --- | --- | --- |
| 员工桌面端 | 本地对话与个人 Skill 草稿、项目、文件操作、成果预览、保存到本地、创建和使用 Skills | 员工 Windows 或 macOS 电脑 |
| 本地助手与 DSH | 运行获准工具、访问授权文件、调用公司服务、执行本地任务 | 员工电脑；仅受控本机连接 |
| 员工网页端 | 使用共享项目、公司知识、公司模型和 Skills，查看后台任务，上传下载文件；聊天历史保存在当前浏览器本地 | 浏览器 |
| 管理后台网站 | 账号和权限、模型与额度、NAS 来源、技能审核、任务和版本管理 | 管理员浏览器 |
| 公司业务后端 | 身份验证、授权、共享数据、连接配置、任务队列、技能仓库和审计 | 公司服务器 |
| 服务端执行环境 | 网页端任务及需要持续跟踪的后台任务；各用户和任务相互隔离 | 公司服务器上的受控执行环境 |
| NAS 连接服务 | 访问获准目录、解析与索引资料、保存归档，传递并执行资料权限 | 可访问 NAS 的内网环境 |
| 外部服务连接 | 对话、图片、视频生成；通过对应协议或 MCP 工具接入 | 外部服务或公司内网模型服务 |

管理后台是管理员使用的网站，后端服务是客户端和管理网站共同使用的接口与业务逻辑。试点时可以同机部署，不要求从第一天建设多机集群。

## 4 角色与权限

| 角色 | 允许的主要行为 | 边界 |
| --- | --- | --- |
| 员工 | 使用获准模型和资料，管理个人项目、任务、连接和技能草稿，提交技能发布 | 不能通过客户端参数修改公司授权 |
| 部门负责人或部门管理员 | 在公司授予的范围内开通管理本部门员工账号、项目、内容和额度 | 不自动取得其他部门管理权、公司模型密钥或 Skill 审核权 |
| 技能审核员 | 按授权部门和发布范围查看技能提交包、作者主动纳入的来源片段、测试摘要与版本差异；审核发布 | 无权浏览或远程拉取员工本地聊天记录与未提交草稿；本部门审核权不等于跨部门或全公司发布权 |
| 公司管理员 | 管理账号、角色、公司连接、知识来源、发布范围、额度、客户端版本和系统配置 | 管理能力须由后端接口授权；不因此取得员工本地聊天记录或电脑系统权限 |

所有公司接口都在服务端校验身份和资源权限。前端隐藏按钮只是界面行为。管理员创建、禁用、重置账号和修改授权必须记录操作。

本地全盘访问、公司 NAS 权限和 Skill 工具权限是不同的授权范围。不得相互替代。

### 4.1 部门组织与账号归属

ORG-01：公司管理员创建、重命名、启停部门，设置唯一部门标识、名称、负责人和获授权管理员、审核员。名称变化不更换部门标识；有成员或共享资源的部门须先完成转移或归档，不直接级联删除账号与技能。

ORG-02：首版默认每位员工有一个主部门、一个独立公司账号；创建账号必须指定已启用部门。跨部门协作通过显式资源授权处理，不要求重复建立员工账号，也不使用全部门共用的账号密码。多部门任职和组织层级继承列为后续扩展，首版不隐式继承其他部门权限。

ORG-03：公司管理员管理全公司的部门与账号；部门管理员仅管理获授权部门的普通员工，不能创建公司管理员、扩大自身权限或把员工迁入无权管理的部门。部门负责人身份本身不自动获得账号管理或审核权限。

ORG-04：账号主部门、部门管理授权、技能归属部门与发布受众均由服务端校验。列表、搜索、数量统计、详情、历史版本、下载、包内素材、审核及公司工具调用使用一致范围，不能通过改部门参数或已知资源编号越权。

ORG-05：调部门保留员工账号及稳定用户标识，更新成员关系后撤销旧权限和登录授权缓存，后续公司请求重新校验。原部门已提交和发布的技能继续归原部门，除非由获准管理员显式移交。个人本地聊天、草稿和成果仍归本人；本地存储键不依赖部门名或部门标识，调部门不移动、上传或公开本地历史。

## 5 首版范围与后续范围

### 5.1 首版必须交付

- Windows 和 macOS 桌面运行框架，共用主要界面和业务能力；员工网页端和管理后台。
- 部门建立、按部门单个或批量开通分发员工账号、首次改密、调部门、登录、退出、停用、角色和资源权限；公司服务地址配置。
- 本地对话、按账号隔离、记录导出导入、项目、文件引用、工作模式、成果预览和保存。
- 至少一种真实图片生成与修改服务，以及一种真实视频生成服务的完整任务流程。
- 本地目录与全盘访问、常见格式解析、文件处理、成果保存和可追踪的执行结果。
- 至少一种实际 NAS 接入方式、授权目录检索、来源引用和归档。
- 对话转 Skill、草稿编辑、试运行、提交、审核、发布、安装、版本更新与回退。
- 公司模型与额度配置，个人模型连接配置和连接测试。
- 长任务状态恢复、失败提示、调用记录和必要的操作审计。

### 5.2 后续可扩展

公司统一登录、自动入离职同步、多组织隔离、更多业务系统连接、更多模型和媒体服务、本地 GPU 服务、语义检索增强、多机调度和更复杂的剪辑流水线。

### 5.3 不计作首版已经完成的能力

- 从对话创建 Skill 不等于训练或微调基础模型权重；基础模型训练不在当前首版范围。
- REA 和界面重建不能恢复其他产品的服务器内部能力；公司的后台能力需独立实现。
- MCP 是工具连接方式，插件背后的服务鉴权、任务、文件传输和权限仍需实现。
- 本地界面、模拟数据或假任务返回值不能替代真实生成、权限验证和跨员工复用验收。

| 我的作品 | 图片、视频和文档结果、所属项目、保存和归档状态 | 页内查看或进入相应任务；不使用常驻右侧抽屉 |
| 个人设置 | 账号、外观、语言、本地记录与导出导入、保存位置、文件权限、后台运行 | 主内容区表单与左侧设置子导航 |

| 账号菜单 | 头像、姓名、公司账号与所属部门、使用情况、模型与服务、设置、帮助、退出 | 左下角向上弹出的小菜单；部门信息只读 |

UI-01：对话默认保留宽主内容区，右侧预览收起。打开后可拖动宽度、缩放、适应窗口、全屏、关闭。关闭恢复原对话宽度。

UI-02：项目、知识、技能、作品和设置不得复用对话的常驻最右侧预览。列表详情通过主内容区路由进入；必要的操作使用居中对话框。

UI-03：头像和姓名整行触发账号菜单。点击外部、再次点击入口或按 Esc 可关闭；菜单支持键盘焦点。

UI-04：顶部文件菜单连接新建任务、打开文件和目录、保存或导出等真实操作；编辑连接撤销、重做、剪切复制粘贴和全选；视图连接侧栏、对话预览、缩放和全屏；帮助连接指南、版本和反馈。不可用菜单需禁用并说明条件。

UI-05：Windows 使用窗口内菜单和窗口控制。macOS 遵循系统窗口与菜单习惯，主要内容风格一致。网页端保留应用导航和操作，使用浏览器自己的窗口控制。

UI-06：Logo、产品名称、品牌色由统一配置或资源入口管理，后续替换不逐页修改。

## 7 账号与公司服务器连接

AUTH-01：安装包可预设公司服务地址。开发和部署可以更改；员工无需逐个设置公司供应商密钥。

AUTH-02：首版允许管理员创建一人一账号。首次管理员初始化不能使用公开写死的弱密码；初始化方式和密码重置须在部署文档说明。

AUTH-03：密码以适当的单向密码哈希保存；登录凭证具备过期、退出和服务端撤销机制。客户端不写入明文账号密码或公司模型密钥。

AUTH-04：登录后加载用户、部门、角色、获准模型、技能、资料范围和客户端策略；失败显示明确原因，不能进入其他人的会话。

AUTH-05：账号停用、权限变更后，公司服务在后续请求中执行新权限，撤销登录凭证；不能承诺收回已经下载到员工电脑的文件。停用和退出不自动删除本地聊天；切换账号后不得展示前一账号的本地记录。

AUTH-06：网络断开时可查看获准的本地记录和本地成果；需要服务器的生成、共享知识和发布明确显示离线，不伪装成功。

AUTH-07：账号管理支持选定部门后单个创建、按模板批量导入员工和批量开通。至少记录员工姓名、公司内唯一登录名、稳定用户标识、主部门、角色、状态及首次改密状态；同名员工可用不同登录名。批量提交先预览，逐行显示重复登录名、无效部门、越权角色和创建结果，不静默覆盖已有账号。

AUTH-08：账号开通或重置可生成每人独立、限期有效的临时初始密码，首次登录须改为员工自己的密码。按部门筛选并逐人提供领取或复制入口，由获授权经办人逐人分发，记录分发操作者、对象、时间和状态。临时密码仅在本次开通或重置结果中供授权管理员取用，不进入持久分发表、审计或普通导出；员工改密后失效，遗失后通过重置处理，后台不能查看员工现用密码。

AUTH-09：账号分发记录与员工资料导出按部门授权；常规导出仅包含账号元数据与开通、分发状态，不包含密码。部门管理员只能重置获准管理的普通员工账号；重置撤销旧登录凭证。个人设置提供修改本人密码，部门归属变更由获准管理员操作。

## 8 对话与项目

CHAT-01：支持文本、多行输入、拖入文件、粘贴图片、附件移除、@ 文件引用、/ 技能选择、模型与工作模式切换、发送和停止。

CHAT-02：工作模式包含问答、规划和执行。规划模式不得执行有副作用的工具；执行模式按当前授权调用工具。模式须落实到工具执行策略。

CHAT-03：按会话显示项目、工作目录、附件、所选技能和来源。工具步骤可折叠，状态至少包含等待、执行中、已完成、失败和已停止。

CHAT-04：历史会话在当前设备的当前账号范围内支持搜索、重命名、删除和继续。会话与成果关联，错误消息不能替代或覆盖既有成功成果。

CHAT-05：完整消息、可观察工具步骤、会话索引和本地附件引用保存在员工本机；桌面端按操作系统用户、公司和员工账号隔离。公司服务不提供员工历史会话的集中上传、远程列表或管理员浏览接口；NAS 不自动备份聊天。

CHAT-06：换电脑或在另一设备登录同一公司账号，不自动出现旧设备聊天。支持由员工主动导出、导入和备份本地记录；导出前展示内容和目标位置，不包含密钥。导入归入当前获确认的本地账号空间，去重并保留成果引用失效提示，不覆盖其他账号记录。

CHAT-07：调用公司网关或外部模型时，会发送本次任务所需的已选上下文、片段或素材；界面须能说明所用服务及发送范围。服务器可以为请求转发进行临时处理，但不得将上下文另存为员工聊天档案，不在日志、调用追踪和审计中留存聊天正文或完整模型请求响应；外部供应商的数据处理规则另按所接服务说明。

CHAT-08：员工网页端首版使用当前浏览器配置文件、站点及公司账号隔离的持久本地存储，不隐式转为服务端会话库。清除站点数据、使用隐私模式或更换浏览器可能丢失或看不到记录，设置页提供说明及导出入口。与同机桌面助手共享本地记录须明确配对和授权，首版不默认互通。

CHAT-09：个人 Skill 草稿、来源选择和完整试运行对话保存在本机。本地删除聊天不会删除已经明确提交的平台 Skill 包；撤回、停用或删除共享内容通过对应的平台操作处理。网页端遵循同样的本地草稿与主动提交规则。

PROJ-01：支持创建、编辑、搜索、进入项目，以及关联对话、文件、技能和成员；共享项目的成员和范围变化由后端校验。个人项目和对话关联保存在本地，共享项目的公共配置与成员关系保存在服务端；加入共享项目不会上传聊天。

PROJ-02：项目公共指令、参考资料、默认模型和输出位置可作为项目上下文；新建任务须显示哪些上下文已被引用。共享项目里只展示明确提交的资源和任务状态；本机对话与项目的关联保留在本地，不向成员公开会话索引或全文。

## 9 模型和外部服务连接

MODEL-01：区分公司连接和个人连接。管理员维护公司连接及部门和员工授权；公司连接在员工端按权限只读。公司策略决定是否允许个人连接。

MODEL-02：连接字段至少包括显示名称、服务用途、协议或适配器类型、服务地址、密钥或鉴权配置、模型标识、能力声明和启停状态。

MODEL-03：提供连接测试和模型列表获取；服务不提供列表时可手动填写模型标识。测试须验证所选用途的实际接口，显示错误原因；不以服务地址可访问代替能力可用。

MODEL-04：默认对话、图片和视频服务分别选择；按连接能力过滤选项。对话 API、Responses、Anthropic、图片 API、视频异步 API 和 MCP 接口不能假定格式相同。

MODEL-05：GPT-6 系列可作为需求理解和调度模型，图像生成由所接图像能力执行；Claude Opus 5.5 可负责脚本与分镜，视频生成由 Seedance 等视频服务执行。具体标识按已开通的服务配置，不能在业务流程中锁死名称。

MODEL-06：公司密钥在服务端受保护保存、只返回脱敏信息；个人连接密钥按运行环境安全保存。日志、导出和 Skill 包不得包含密钥。

MODEL-07：公司连接须执行额度和并发限制。显示估算用量与最终确认用量的区别；超额、限流和权限不足返回可理解的提示。

MODEL-08：切换模型或停用连接不得静默转用未经授权的其他服务；运行中的任务记录原始服务和模型信息。

## 10 图片创作

IMG-01：支持文生图、参考图生成、图片编辑和连续对话修改；仅显示实际服务支持的功能。

IMG-02：支持配置比例、尺寸、数量和输出格式；不支持的参数在提交前提示，不能假装生效。

IMG-03：输入可来自授权本地文件、项目素材和公司资料。记录所用附件、提示词版本、服务、模型和任务关系。

IMG-04：成果保留版本，支持预览、继续调整、另存、打开所在目录和按权限归档 NAS。编辑结果不能默认覆盖原图。

IMG-05：供应商成功返回后，将实际文件写入选择的保存位置并验证文件可读；保存失败与生成失败分别展示，保留可重试下载的信息。

## 11 视频制作与长任务

VID-01：支持需求到脚本、分镜、提示词，以及接入服务支持的文生或图生视频。时长、比例、分辨率、音频和参考输入根据服务能力配置。

VID-02：任务至少区分待提交、已提交、排队、生成中、可下载、保存中、已完成、失败、取消中和已取消。供应商不提供进度时使用状态提示，不编造百分比。

VID-03：公司后台保存供应商任务编号，跟踪或接收回调；关闭客户端不丢失已提交任务。重开后可查看状态并继续下载，电脑离线时不承诺写入其本地硬盘。后台仅保存执行所需的已提交提示词、素材引用、任务状态和结果，不保存完整聊天；任务输入与结果须配置保留及清理规则。

VID-04：提交和重试应避免重复创建和重复扣费。请求超时但提交结果未知时先查询或核对任务，不能直接无限重发。

VID-05：停止本地等待与供应商确认取消须区分；供应商不支持取消时说明实际状态。

VID-06：生成结果及时持久保存，避免临时链接过期。支持失败下载重试、重复文件处理和归档状态查询。

## 12 本地文件与权限

FILE-01：桌面端支持项目目录与全盘模式。全盘指当前系统账号及系统授权允许访问的资源，不绕过操作系统限制，也不自动提权。

FILE-02：提供目录浏览、文件名和内容搜索、读取解析、创建编辑、复制移动、批量整理和删除能力。破坏性操作须有可追溯执行结果和适当的恢复或确认策略。

FILE-03：首版解析范围包括 TXT、Markdown、CSV、JSON、PDF、DOCX、XLSX 和常见图片；视频至少支持元信息和已接入的处理流程。加密、损坏、超大或不支持格式返回明确原因。

FILE-04：本地访问范围与上传给模型的范围分别控制。按任务读取和发送需要的片段或素材，不默认上传整盘文件。

FILE-05：授权可以撤销。文件工具和子进程需要实际执行边界；仅通过 UI 或提示词声明目录范围不构成限制。插件不能绕开当前授权。

FILE-06：网页端支持上传和下载；需要操作员工本地目录时，通过已连接且获授权的本地助手。未连接时显示连接要求，不提供虚假的全盘访问状态。

FILE-07：本地助手仅通过受认证的本机通信连接客户端，网页连接需要明确的来源与配对约束。服务器不能任意命令员工电脑执行未授权任务。

FILE-08：默认输出位置可设置。写入时处理重名、无权限、磁盘不足和路径失效；保留已有文件，成功记录实际路径。

## 13 NAS 与公司知识

KNOW-01：管理员配置 NAS 接入方式、连接凭据、获准目录、同步计划和访问范围；凭据保留在连接服务。

KNOW-02：首版优先实现目录、全文搜索、文档解析和可点击来源；根据真实检索效果增加语义检索，不能以向量库代替原始文件与权限。

KNOW-03：按员工、部门和项目执行资料授权，在内容传入模型前完成过滤。源文件和派生的文本、索引、缩略图、下载入口须遵循同一权限。

KNOW-04：无法映射源 ACL 时，必须采用管理员明确配置的目录白名单和人员范围；未知范围默认不开放。

KNOW-05：显示来源路径、文件版本或更新时间、同步状态。删除、移动和授权变化须刷新可见性；不能长期引用已撤权的缓存内容。

KNOW-06：成果由员工明确归档到有权写入的位置；NAS 不可达时保留本地成果并标记待归档，重连后可重试且不重复写入。

KNOW-07：不向公网直接暴露 NAS 文件共享端口。云端部署时需另设可达 NAS 的受控连接方式。

## 14 对话转 Skills 与公司技能仓库

### 14.1 提炼与编辑

SKILL-01：会话工具栏和技能中心提供从对话创建入口，支持从当前设备本人本地记录中选择一段或多段会话及附件。作者预览用于提炼的内容；选中来源不等于同意将原始记录发布。调用模型提炼时，仅发送本次所选必要内容，并遵循 CHAT-07。

SKILL-02：从任务目标、用户修正、认可的成果和可观察工具步骤提炼流程；不机械复制全部聊天记录，也不要求取得模型内部推理内容。

SKILL-03：将产品名、素材、主题、尺寸、输出位置等可变内容转为输入参数；保留必要的质量要求、示例、参考资料和失败处理。

SKILL-04：作者可编辑名称、说明、适用场景、触发条件、输入输出、流程、工具和模型用途、引用资料及默认参数。模型连接使用可绑定的配置，不写入作者的个人密钥。

SKILL-05：按需要生成 SKILL.md、参数和依赖清单、参考资料、模板、脚本或资产。包清单记录作者、版本、执行位置、操作系统适用性和权限要求。原始会话来源映射保存在作者本地；发布包只包含作者明确选择纳入的示例或来源摘录及其包内引用，不携带可远程读取本地会话的链接。

SKILL-06：发布前检测并处理个人绝对路径、账号凭据和不应共享的资料；可移植素材进入受权限管理的资源，目录通过运行时选择或授权绑定。

### 14.2 试运行与发布

SKILL-07：新技能先进入本机个人草稿，未提交时不上传平台。作者用不同于原始会话的新素材和参数试运行，查看结果、工具调用、失败原因及版本变化，再修订；发布测试摘要与本地完整测试对话分开管理。

SKILL-08：使用范围分为本机个人、本部门、指定多个部门或全公司。本机个人保存与使用不需要上传或公司发布审核；平台提交默认选择本部门，跨部门或全公司开放须按发布范围获得审核。首版不提供个人草稿的默认云同步。

SKILL-09：提交包冻结版本。状态包括草稿、测试中、待审核、退回修改、已发布、已停用；审核期间继续修改应形成新草稿，而非静默改变待审包。

SKILL-10：审核员可查看提交内容、作者主动纳入的来源摘录、工具和资料范围、版本差异与测试摘要；可填写意见、退回或批准。查看来源仅展示提交包中的摘录，不回连作者电脑或读取原始聊天。补充材料须由作者再次选择并提交。记录操作者、时间和理由。

SKILL-11：已发布包不可原地覆盖。新版本经过同样的变更、测试和发布过程。支持指定版本、更新、停用和回退；运行中的任务固定所用版本。

### 14.3 安装与复用

SKILL-12：员工在获准范围内发现、安装、卸载和使用技能。安装前检查工具、模型、系统与资源依赖；缺少依赖时给出可操作提示。

SKILL-13：B 员工在新会话中填写参数并运行，不需要 A 的完整对话或机器环境。公司知识和工具调用按 B 的账号与当前本地授权执行。

SKILL-14：区分流程型 Skill 和带代码插件。可执行依赖声明、来源检查、版本约束和运行边界需要额外验证；不能把导入文本直接当作可无约束执行的程序。

SKILL-15：作者可用新的成功对话提议改进，系统生成差异和新版本；发布变更仍保留测试和审核记录。下载或安装员工是否立即更新由更新策略决定。

### 14.4 主动提交的数据边界

SKILL-16：提交前展示实际上传清单与范围，包括 Skill 文件、参数、依赖、明确纳入的资源和来源摘录、测试摘要及发布元数据。采用显式文件清单打包，不递归上传聊天目录、草稿工作区、完整试运行日志或未选择附件；不得包含个人密钥与机器绝对路径。

SKILL-17：其他员工下载的是获准版本的 Skill 包及获准资源，使用自己的输入、模型绑定和文件授权执行；运行产生的完整对话与个人修改仍保存在使用者本机。下载技能不下载作者完整会话，不授予访问作者电脑的能力。

### 14.5 部门提交、审核与分发

SKILL-18：平台 Skill 分别记录创建者、归属部门和发布受众；归属不等于受众。新提交默认归员工当前主部门，其他归属须有显式管理授权；服务端从当前成员关系核验，不采信本地草稿中缓存的部门。待审核包及版本固定其归属与申请范围，作者调部门不自动改变已有提交或发布内容。

SKILL-19：本部门发布由获该部门审核权的审核员处理；指定多个部门或全公司发布由获相应公司发布权的审核员批准。普通部门审核员不能扩大范围。扩大既有版本的受众须形成新的发布申请并重新审核，不仅修改客户端标签；待审和退回内容不在普通员工技能列表中开放，提交者与获授权审核人员在当前权限范围内跟踪状态。

SKILL-20：技能中心按本部门、跨部门共享、全公司筛选展示当前员工获准内容，并显示归属部门、作者、版本、受众和安装状态。支持员工自助下载，也支持获授权管理员向许可范围内的部门推荐或下发安装通知；普通流程型 Skill 经员工确认后安装，带可执行代码的插件仍须完成权限与依赖检查。分发不能超出已批准受众，不默认静默安装或执行代码。

SKILL-21：调部门、停用或撤权后，停止后续无权的查看、下载、更新、审核和公司服务调用；客户端刷新授权后将失权安装项标为不可用。已下载文件和完全离线执行的本地副本无法保证收回，不承诺远程抹除。原部门技能由该部门获授权人员继续维护，不能因作者调部门自动迁给新部门；再次提交本地草稿时重新校验其公司资料依赖与分享权限，不能借跨部门 Skill 发布扩大底层资料授权。

| 位置 | 保存内容 | 不自动接收的内容 |
| --- | --- | --- |
| 员工桌面本地存储 | 完整对话、消息、工具步骤、个人项目、项目与对话关联、本地附件引用、生成成果、Skill 草稿、完整试运行记录、安装包及本地设置 | 其他员工记录；其他设备聊天 |
| 员工网页本地存储 | 当前浏览器与账号的对话、个人项目、草稿与本地引用；大文件按浏览器能力明确处理保存位置 | 桌面端或其他浏览器的历史记录 |
| 公司业务数据库与包存储 | 用户、部门、角色、共享项目与成员、授权、公司连接、模型能力、知识来源、提交的 Skill 包及版本、审核、任务、用量、审计 | 员工完整聊天、未提交草稿、本地会话索引及来源映射 |
| 公司任务暂存区 | 执行所需的已提交提示词、输入素材或引用、供应商任务编号、状态、下载信息和待保存成果，按配置期限清理 | 与当前任务无关的历史消息、整套本地附件 |
| NAS 与知识索引 | 已授权公司资料、显式归档的成果、按发布清单纳入的共享资源 | 员工聊天目录、个人草稿和整盘文件 |

用户、共享项目成员、共享资源归属和授权范围属于服务端事实；本地会话归属与来源映射属于本机事实。两者使用各自存储和接口，不用一套服务端会话库承载员工聊天。任务可以关联使用者、共享项目、服务和技能版本；对话到服务端任务编号的映射保留在本地。

公司侧补充部门、成员关系及变更、分部门管理与审核授权、账号开通分发状态、Skill 归属部门、版本受众和分发记录。用户与部门使用稳定标识关联，部门调整不生成新员工身份；Skill 受众使用明确部门标识集合或全公司范围，不能用显示名称或客户端筛选条件代替授权。审计记录部门、成员、受众和归属移交的操作者及前后变化，不记录密码或员工聊天。

### 16.2 传输、日志与备份

本地保存不等于模型完全离线运行。调用时会按 CHAT-07 将必要上下文发给指定服务；提交视频等后台任务也会上传其执行所需输入。服务器不将这些输入拼接或沉淀为员工完整对话，不以调试、异常追踪或用量审计绕过本地记录规则。

公司审计保留操作者、动作、资源或任务编号、状态、时间和用量等元数据；敏感输入与错误正文须脱敏。网关、代理、执行器及日志采集默认关闭模型请求响应正文落盘。密钥与可供 UI 展示的连接元数据分开保存。

公司备份覆盖共享业务数据库、已提交技能包、配置元数据和按策略保留的任务成果，不扫描员工电脑或备份本地聊天。员工本地记录由主动导出、导入和本地备份恢复，换设备不自动恢复；导出附件与成果须由员工明确选择，路径引用不能冒充文件备份。

共享业务数据与任务状态持久化，应用重启后可恢复；正在提交且结果不明的任务应可核对，不能伪造完成。平台保留的待审包、审核记录和已发布内容有独立生命周期，不受作者本地聊天删除影响。

## 17 非功能与运行要求

- 内部和远程入口使用受控的 HTTPS 服务；本地助手采用受认证的本机通信。
- 采用按用户和任务的执行环境与资源限制；通用 DSH 插件运行不能替代公司级隔离与授权。
- 列表支持搜索、分页和明确空状态；长操作显示进行中、失败原因与恢复入口。
- 大文件按需流式处理；解析、索引、生成和下载有超时、取消与并发边界。
- 重要操作可审计，任务和调用有可关联编号，便于排查跨客户端和服务器问题。
- 试点可单机部署业务服务、数据库和受控执行任务，NAS 独立保存资料；后台任务失败不能拖垮账号和知识服务。
- 公司备份范围覆盖共享业务数据库、已提交技能包、配置元数据和必要成果，需实际验证恢复；员工本地记录另做本地导出导入验证，不自动纳入公司或 NAS 备份。
- 桌面包包含明确依赖；Windows 与 macOS 使用各自环境验证。签名、公证和公司分发策略作为正式交付条件。
- 页面在常用笔记本宽度下无不可达主操作；窄窗口允许收起导航，不能让表单和对话输入被裁掉。

暂定试点容量参数：单台应用服务器 8–16 核 CPU、32GB 内存、500GB–1TB SSD，模型走外部 API 时不要求 GPU。这是待压测的起步估算，不是已验证的并发承诺。

## 18 关键异常处理

| 情况 | 必须表现 |
| --- | --- |
| 登录过期、停用或撤权 | 停止新的公司请求，提示重新登录或联系管理员；不能显示其他用户数据 |
| 模型未配置、余额不足、限流 | 明确原因和可用恢复动作；不能返回伪造的生成结果 |
| 生成提交超时、结果未知 | 保留请求记录，核对供应商任务后决定重试 |
| 客户端退出或电脑离线 | 已提交后台任务继续可查询；本地落盘等客户端恢复后执行 |
| 本地保存失败 | 区分已生成与未保存，保留下载或另存能力 |
| NAS 离线或无权归档 | 保留本地成果，明确待归档或权限失败 |
| 文档解析失败 | 标记具体文件，保留原文件，不将空文本当作成功入库 |
| Skill 缺模型、工具或素材 | 安装或运行前提示缺失项，不静默改用其他授权 |
| 审核期间作者修改 | 产生新草稿，待审版本保持不变 |
| 技能停用或回退 | 新任务按发布状态和策略处理，保留既有任务版本记录 |

| AC-14 | 管理员停用与额度 | 后续公司请求执行停用或额度变化，不能仅改变页面显示 |

| AC-18 | 打包与部署 | 安装、启动、升级和卸载流程有记录；正式分发满足公司签名与发布要求 |
| AC-19 | 对话只在本地持久保存 | 重启客户端可恢复本机聊天；检查网络请求、服务端数据库、代理和执行日志，除所需推理上下文与明确任务输入外，没有完整聊天归档、会话索引上传或正文日志；后台和管理员接口不能浏览本机聊天 |
| AC-20 | 发布包边界 | A 选择来源后可分别预览提炼输入和实际上传文件；平台只收到所确认 Skill 包、摘录和测试摘要，无完整聊天文件、未选附件、个人密钥或绝对路径；审核来源入口不连接 A 的电脑 |
| AC-21 | 网页与换设备 | 同账号换电脑或浏览器不出现旧聊天；原浏览器重开仍可查看本地记录；清除数据风险和导出入口可见，未配对时不能读取桌面聊天 |
| AC-22 | 本地隔离与恢复 | 同一电脑切换公司或员工账号互不显示聊天与草稿；主动导出、导入可恢复选定记录，重复导入不重复创建，缺失附件明确提示；删除本地聊天不误删已发布 Skill |
| AC-23 | 按部门建立和分发账号 | 公司管理员建两个部门，分别单个或批量开通独立员工账号，重复和非法部门逐行报错；部门管理员不能管理他部门或提升角色；临时密码首次改密后失效，现用密码不可查看，普通导出及审计无密码 |
| AC-24 | 部门技能可见与分发 | A 部门技能默认仅其受众可发现和下载；B 部门不能通过搜索、数量、详情、旧版本或素材地址取到内容；批准共享给 B 后可安装，未列入范围的 C 仍不可访问；推荐或下发通知不能扩大范围 |
| AC-25 | 分范围审核 | 本部门审核员可处理本部门提交，不能审核他部门或自行批准跨部门、全公司开放；获公司发布权的审核员批准后按申请范围生效，原有版本扩大受众须重新审核 |
| AC-26 | 调部门与技能归属 | 员工由 A 调往 B 后用户标识和本地记录不变，后续请求失去仅向 A 授予的资源权限；客户端刷新后旧安装项按授权标记，原部门已提交和发布技能继续留在 A，可经授权移交；不将本地历史传给 B，也不声称能收回离线文件 |
