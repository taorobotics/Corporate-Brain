# v0.27.5 · 长代码输出与自动接续修复

## 员工端更新

- 修复制作视频和项目代码时，单次输出被固定为 12,000 Token，思考或长源代码用完预算后直接失败的问题。DeepSeek Flash/V4 制作请求采用当前官方 Harness 适配器使用的 256,000 Token 输出预算；其他兼容模型沿用供应商默认预算，不再强加统一的 12,000 上限。
- 服务商以长度边界结束响应时，保留已输出的 JSON 和源代码，自动接着补完；只携带一份已生成前文，不重复塞入每一段历史。完整性与语法检查通过后才渲染和交付，不把截断代码当作成片。
- 移除动画源代码“16,000 字符以内”的提示限制，并扩大完整动画源码可校验的范围。制作生成阶段改为检测持续无新内容，不再按固定四分钟切断仍在输出的请求；停止、账号与模型授权检查继续生效。
- 制作期间定期保存当前任务的私有生成草稿；网络中断或模型反复没有补充正文时保留草稿，避免无效重试。成功后只交付完整源码、素材和成片，清除中间草稿；用户取消任务时仍按原流程清理该任务。

## 客户端与服务器更新

本次修复位于公司业务服务器，Mac mini 备份升级后，已有客户端重新打开或重试任务即可使用；桌面安装包同时递增版本供自动更新。Windows 通过左下角检查更新，下载校验后点击安装，沿用原目录与公司地址并重启；Mac 使用对应架构 DMG 替换。首次安装需填写公司提供的 HTTPS 地址。

管理员先停止服务并备份数据库、密钥及部署配置，再部署服务器包，沿用原有数据、权限、NAS、模型和 HTTPS 设置。云服务器只同步安装包镜像，Mac mini 继续承载公司业务。

## 实际验证与边界

回归覆盖 JSON 字符串及转义中间截断后的多段接续、重复代码原样保留、只有思考没有正文时的恢复、无进展停止、网络断流草稿保留、用户取消、持续输出无固定总时限，以及经真实公司接口生成完整项目文件的链路。测试采用隔离账号与合成模型服务，不声称这些回归验证了真实模型的内容质量。

Windows 和 Mac mini 均通过 152 项 Node 测试、5 项 NAS 测试与生产构建。Windows 原生成果链路 5 项、Mac 原生成果链路 6 项检查通过；Mac 包括 2 秒、1280×720 视频的实际渲染和本地解码。三平台公开安装与更新验收以 Release 的检查记录为准。

Mac mini 已升级为 0.27.5，并保留原有 224 个账号、13 个部门、14 个 NAS 来源、3 个普通技能、模型配置和密钥。Windows 通过严格 HTTPS 核对运行中的入口和网页资源与已构建文件一致。

使用实际配置的 DeepSeek Flash，通过隔离员工账号在业务接口提交最小 Canvas 动画制作任务，完成 2 秒、1280×720、24 fps 视频渲染，逐个接收源码、计划和成片并核对 SHA-256，以 FFmpeg 实际解码成片。确认保存后服务端状态为 saved、任务字节数为 0；临时账号、会话与验收任务已清理。此小任务验证实际服务、生成和渲染链路；长度截断接续由可复现的合成服务测试覆盖，没有声称真实模型输出过 256,000 Token，也没有改写员工原来的失败任务。
