# v0.12.0 · 回答操作与反馈管理

## 员工端更新

- 回答下方新增复制、点赞、点踩、问题反馈、分享与保存 Markdown；显示本条模型、真实 Token 用量与回答时间。没有返回用量的历史回答明确标注未返回。
- 反馈送达公司管理后台。默认只提交评价与说明，主动勾选并预览后才附上当前问题与回答，不附其他轮对话、思考过程或附件文件。
- 新客户端支持受限的原生复制接口，旧客户端使用选中文本复制兼容路径。
- Mac mini 可按 Windows / Apple 芯片 / Intel 平台分别分发已验证安装包。旧客户端通过现有平台信息选择更新通道；新客户端另带平台请求头。完整公开 Release 仍要求三平台齐全。

## 管理后台

新增“回答反馈”表格：提交人、部门、模型、评价、问题类型、说明、状态和时间；支持搜索、评价/状态筛选、分页、详情、内部处理备注。仅公司管理员可访问。重复提交更新同一条记录；内容改变后回到待处理，重复网络重试不重开已处理记录。并发处理检测冲突。

## 客户端与服务器更新

客户端从公司入口加载网页，需先更新 Mac mini 服务，已有客户端重新打开即可使用网页功能。原生复制与平台请求头随 0.12.0 安装包更新。用户在左下角发现新版本后主动下载、校验并打开安装包。

服务器更新前停止服务并备份项目 data/config 及启动脚本；保留账号、部门、模型配置和加密密钥。新增 feedback 表只保存用户主动提交的记录，不迁移或收集本地完整聊天。

本批按用户要求以 Mac mini 私有局域网交付为主，GitHub 同步继续暂停。Windows 与 Apple 芯片 Mac 完成原生测试后分别激活内部更新通道；未完成原生验证的平台保持上一份完整版本，不以源码或交叉构建冒充三平台完整 Release。

## 验证与签名

验证记录随本地交付目录提供，覆盖服务端反馈认证、权限、上下文选择、重复请求、分页与限流，真实 Electron 复制/反馈/后台处理，以及更新校验、断点下载、坏包拒绝和旧客户端兼容。

Windows 无可信代码签名，Mac 为 ad-hoc 签名且未公证。未在用户办公系统执行安装/卸载生命周期测试；不宣称所有员工已安装。Intel Mac 原生验收及公开完整 Release 不在本次私有双平台交付完成范围内。
