# NAS 只读目录浏览

公司知识支持通过服务器连接内网 SMB 共享，显示获准目录的文件名、类型、大小、修改时间，并按名称搜索当前目录。文件内容预览、下载、递归索引、AI 检索和写入归档尚未开放；不会因为接通目录就把文件送给模型。

## 服务器准备

运行环境为 Python 3.9 或更新版本，以及 `server/nas-requirements.txt` 中固定版本的可选依赖。将依赖安装在本项目私有目录或虚拟环境中，不改变系统 Python 或其他项目。例如：

```sh
python3 -m pip install --only-binary=:all: --target /absolute/project/runtime/nas-python -r server/nas-requirements.txt
```

设置 `BRAIN_NAS_PYTHON` 为 Python 的绝对路径，`BRAIN_NAS_PYTHON_PATH` 为上述依赖目录，然后按原方式启动服务。安装过程中保留依赖包自带的许可文件。服务器更新包不包含 Python 解释器、可选依赖、NAS 密码或公司文件。

连接要求：服务器可访问 NAS 的局域网 IPv4 和 445 端口，NAS 支持 SMB 3 加密及账户认证。连接启用协议签名与会话加密，不降级到明文或来宾身份，不自动跟随 DFS 或目录链接。

## 部门和资料源

1. 在“管理后台 → 账号和权限 → 部门”建立实际部门，按真实名单将员工归入对应部门。NAS 账号与公司大脑员工账号独立，不应复制 NAS 密码作为员工登录密码。
2. 在“管理后台 → 公司知识”添加资料源：内网 IP、真实共享名、可选子目录和该部门 NAS 账号。不要将文件资源管理器显示的别名当作真实共享名。
3. 明确勾选允许浏览的部门。多个部门访问同一目录但使用不同 NAS 账号时，分别建立资料源；同一部门的多个共享也分别建立。
4. 保存并检查连接，验证通过后启用。检查仅返回是否可列出根目录与项目数量，不向管理员返回文件列表；管理员读取资料同样必须满足部门授权。
5. 员工重新打开“公司知识”，即可看到本部门已启用的资料源。旧客户端加载新服务器界面即可使用。

NAS 自身的 ACL 仍是上限，公司大脑部门授权只进一步缩小范围。每次目录读取都复核当前员工、部门、会话与资料源；读取期间发生停用、改部门或撤权时，不返回旧结果。目录列表不持久缓存，不把路径或文件名写入审计日志。审计仅记操作者、资料源和操作类型。

目录操作限时、限并发并按员工限流。密码错误后暂停该资料源验证一分钟，防止持续重试触发 NAS 锁号。每次展示最多 500 项，超过后可通过当前目录名称搜索缩小范围；搜索不代表全盘检索。SMB 工作进程只请求列目录及读属性权限，禁止写入、创建文件与读文件内容；所有目录父句柄保持打开且不共享写入/删除，阻止遍历期间父路径被替换。

## 凭据与备份

后台密码字段只接收新值，不返回原密码。编辑时留空保持原值，显式录入的新值按原字符保存，不去掉空格、不解释反斜杠或 shell 字符。数据库中用原有 `secrets.key` 进行 AES-256-GCM 加密；工作进程通过标准输入接收一次性连接参数，密码不进命令行、浏览器响应或日志。

备份 `platform.sqlite` 时一并保管匹配的 `secrets.key`。本地管理员准备文件应放在 Git 忽略、访问权限受限的目录，仅用于导入；服务器成功导入后移除临时明文。公司私密配置、NAS 资料、数据库和密钥均不能进入 GitHub 或安装包。
